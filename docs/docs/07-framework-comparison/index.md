## 7.1 对比维度总览

| 维度 | Flask | Django | FastAPI |
|------|-------|--------|---------|
| 同步/异步 | 同步为主 | 同步为主，ASGI 部分 | 原生异步 |
| 类型系统 | 无 | 无 | Pydantic 强类型 |
| 自动文档 | 需插件 | DRF + drf-spectacular | 内置 |
| ORM | 自选 | Django ORM（强绑定） | 自选 |
| 学习曲线 | 低 | 中高 | 低中 |
| 性能 | 中 | 中 | 高 |
| 项目脚手架 | 轻 | 重（admin/migrations/auth 内置） | 轻 |
| 适用 | 小型/传统 | 全功能大应用 | API/微服务/LLM 后端 |

待补充：讲同步库（requests、psycopg2）与异步库（httpx、asyncpg）的生态分裂，`sync_to_async` 桥接的代价，为什么混用容易踩坑。

## 7.3 类型系统与数据建模

待补充：Flask 靠手写校验或 marshmallow，Django 靠 Form/Serializer，FastAPI 靠 Pydantic 注解。对比同一接口三种框架的入参校验代码量。

---

## 7.4 文档与契约

待补充：Flask 需 flask-smorest 等插件手写 schema，Django 靠 drf-spectacular 从 Serializer 推导，FastAPI 从类型注解自动生成。对比维护成本。

---

## 7.5 ORM 与数据访问

待补充：Django ORM 强绑定但功能完备（migrations/admin）；FastAPI 不绑定 ORM，SQLAlchemy 2.0 async / SQLModel / Tortoise 各有取舍。对比异步查询写法。

## 7.7 学习曲线与生态成熟度

待补充：Flask 上手最快但大型项目要自己搭架构；Django 自带架构但概念多；FastAPI 上手快且自带结构，但生态比 Django 年轻。给出团队引入建议。

---

## 7.8 适用场景矩阵

| 场景 | 推荐 | 理由 |
|------|------|------|
| 内部管理后台 | Django | admin/migrations/auth 内置 |
| 单页应用 API 后端 | FastAPI | 异步 + 自动文档 |
| 微服务 | FastAPI | 轻量、高性能 |
| LLM 应用后端 | FastAPI | 流式响应、Pydantic 契约 |
| 传统企业系统 | Django/Flask | 生态成熟、同步驱动齐全 |
| 高并发 I/O 密集 | FastAPI | 异步原生 |

## 7.9 为什么 LLM 后端偏爱 FastAPI

待补充：从流式响应（SSE/StreamingResponse）、Pydantic 与 LLM 结构化输出契约、异步并发调用多个 LLM、与 LangChain/LangSmith 生态契合四个角度分析。

## 7.10 Django 全家桶 vs FastAPI 组合优先

待补充：Django"自带一切"降低选型成本但耦合高；FastAPI"按需组合"灵活但需自行选型。对比团队规模与项目阶段对两种哲学的适配。
